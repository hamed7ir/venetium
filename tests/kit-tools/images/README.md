# kit-tools/images - provenance and development tools of the images page

Nothing here is shipped with the kit. The shipped files are `kit/images.html`, `kit/lib/images-lib.js`, `kit/data/images-*.js`,
`kit/images/decode/{valid,broken}/*` and `kit/manifest/images.tsv`; the binaries and the two data files are generated by these tools.

| file | what it is |
|---|---|
| `gen_valid.py` | builds the 53 valid test files (own generated lossless files, copies of Chromium-tree test files) and `valid.json` (metadata, expected values) |
| `gen_broken.py` | builds the 55 broken files (named edits of valid files, plus Blink regression files copied from the tree) and `broken.json`; the `allowed` list of each file is the host's expectation ("corrupt" is allowed for none) |
| `pack.py` | packs both outputs into `kit/images/decode/`, `kit/data/images-*.js` and `kit/manifest/images.tsv` (112 rows: page, lib, 2 data files, 108 binaries); hashes `images.html` and `lib/images-lib.js` as they are when it runs |
| `imgtools.py`, `vp8l.py`, `jpegseg.py` | helpers of the generators (PNG/GIF/BMP/ICO writers and PNG/GIF readers written from the format specifications, a VP8L encoder with deliberate defects, a JPEG segment parser) |
| `x86ref.json` | the checksums the x86 build produced for the 14 lossy / wheel files (the "REGRESSION vs the x86 build" rows; not independent expectations). A file whose record has `semi` > 0 (pixels with 0 < alpha < 255: wheel-png, wheel-webp, wheel-avif) gets an info row instead of a check, because the canvas un-premultiply rounds ties differently on ARMv7 NEON than on x86 |
| `alpha_survey.py` | which valid files have semi-transparent pixels: host-side decode of the shipped files (PNG, GIF, BMP, ICO, WebP / AVIF container level) and, with `--browser`, a count in the browser under test; checks the `semi` field of `data/images-valid.js` against it |
| `verify_manifest.py` | STRUCTURAL check of `manifest/images.tsv` against the disk and the data records (header, columns, LF, no outside paths, hashes, nothing unlisted) |
| `mutations.js` | page-level mutations of a scratch copy of the kit (see its header for the expected verdict of each; includes an ARMv7 un-premultiply simulation, `sim-armv7-unpremul`) |
| `check_valid.py`, `mkprobe.py`, `probe.js` | development check of the valid files in the browser under test (`NODE`, `VENETIUM_EXE`, `IMG_OUT`) |
| `mutate.py`, `cmp_probe.py` | the first, data-level mutation set (needs a scratch kit folder as argument) and the grid comparison against the source images of the lossy files |

Regenerate (order matters: the page and the lib file are hashed into the manifest, so edit them first, run `pack.py` last):

    set PYTHONDONTWRITEBYTECODE=1
    set IMG_OUT=<scratch folder for the generator output>
    python gen_valid.py && python gen_broken.py && python pack.py && python verify_manifest.py

`IMG_TREE` (default `F:/cr/src`) is the Chromium tree the tree-sourced test files are copied from; `IMG_KIT` (pack.py) is the kit
folder to pack into. The 108 binaries regenerate byte-identically. Do not edit `data/images-*.js` by hand (its manifest hash and the
generator would disagree); change `gen_broken.py` / `gen_valid.py` and run `pack.py`.
